# Задумавшийся

Sim2Real для робота EV3.

## Подключение

Подключение портов на блоке EV3:

1: ультразвуковой датчик
2: правый датчик цвета
3: левый датчик цвета

A: левый мотор
B: правый мотор

## Тесты

Хост, симулятор и кирпич не нужны: тесты читают `.cs` и `.unity` как текст и
собирают модели в памяти.

```
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest
```

Один файл: `python -m pytest tests/test_export.py`, один тест: добавить
`-k test_export_matches_the_trained_policy`.

- `tests/test_contracts.py` — константы, которые продублированы в питоне и в c#:
  версия протокола, размерности наблюдения и действия, порядок колонок в
  `RobotController.Observe` и в `BrickRobot._observe`, отсутствие заданной частоты
  на кирпиче. Плюс `shared/` и `brick/` парсятся питоном 3.9 и не импортируют
  того, чего на кирпиче нет.
- `tests/test_export.py` — обученная сеть и сеть с кирпича дают одни и те же
  вольты, для всех трёх архитектур. Заменяет `check_export.py`: модели строятся
  здесь, обученный прогон не нужен.
- `tests/test_runner.py` — цикл `shared/runner.py` на фальшивом роботе: действие
  лежит в одной строке с наблюдением, из которого посчитано; робот остановлен и
  лог закрыт на любом выходе; цикл нигде не ждёт; расписание политики кончается
  по часам наблюдения.
- `tests/test_inference_timing.py` — синтетические веса бенчмарка несут те же
  ключи и те же формы, что пишет `rl/export.py`: иначе он мерил бы сеть, которой
  на кирпиче не бывает.

## Замеры на кирпиче

Три скрипта. Код уезжает `./sync.sh`, логи возвращает `./fetch.sh`.

```
ssh ev3dev 'cd ponderer && python3 experiments/inference_timing.py'
ssh ev3dev 'cd ponderer && python3 experiments/loop_timing.py [частота] [шагов]'
ssh ev3dev 'cd ponderer && python3 experiments/io_timing.py [раундов] [повторов]'
```

- `experiments/inference_timing.py` — один прямой проход без железа: mlp и lstm
  четырёх размеров на синтетических весах. Ни моторов, ни датчиков не нужно,
  робот может лежать на столе. Сводка в консоль, полный лог по шагам в
  `logs/brick/inference_timing-<utc>.csv`.
- `experiments/loop_timing.py` — весь управляющий цикл с железом, фазами и в том
  порядке, в каком их гоняют `shared/runner.py` и `brick/brick_robot.py`:
  `features`, `net`, `log`, `volts`, `duty`, затем сон до дедлайна, затем `write`
  и `observe`. `body` — их сумма, то есть работа, которая обязана уложиться в
  период. Моторы крутятся, робота надо куда-то поставить.
- `experiments/io_timing.py` — цена одного обращения к железу: свойства ev3dev2
  против сырых дескрипторов, по каждому атрибуту и целиком за `_observe`. Пишет
  нулевой duty и ничего не крутит, робот может стоять на столе.

## Длительность шага

Заданной частоты нет. Цикл на кирпиче идёт так быстро, как получается, и шаг
длится ровно один проход: `features`, `net`, `log`, `volts`, `duty`, `write`,
`observe`. Их сумма — `body` из `loop_timing.py`, она же и есть длительность шага.
Для lstm с hidden 8 и без ультразвука это 19 мс по медиане и 38 мс по p95.

Из 19 мс шага: `net` 7.5 мс, `observe` 2.6 мс, `volts` 2.0 мс, `features` 2.0 мс,
`duty` 1.5 мс, `log` 1.4 мс, `write` 1.2 мс. До того как шаг стал читать и писать
sysfs сам, он занимал 27 мс, из них `observe` 9 мс, `volts` и `write` по 3 мс:
разницу целиком дали дескрипторы, а не арифметика.

Разброс задаёт не цикл. Раз в несколько секунд что-то в системе забирает
процессор на сотни миллисекунд, и в такие окна дорожают все фазы разом, включая
`net` (сброс буфера csv на карту проверен и ни при чём). Отсюда хвост: p95 вдвое
длиннее медианы, а отдельные шаги — вдесятеро. Соседние шаги при этом
скоррелированы, медленные приходят пачками по несколько штук, а не поодиночке.

Сколько длился каждый шаг, видно из колонки `t` в логе прогона: и кирпич, и
симуляция пишут туда свои собственные часы, так что разности соседних строк и
есть измеренное распределение.

Один вызов numpy на кирпиче стоит около 240 мкс, а сеть — это полторы тысячи
умножений, так что шаг измеряется в вызовах, а не в арифметике. Поэтому
`shared/policies/net.py` сложен так, чтобы вызовов было как можно меньше: одно
matvec на все четыре гейта, один tanh вместо трёх сигмоид, смещения вкатаны
последним столбцом, буферы выделены один раз.
